## 功能实现顺序

先完成「搜索 → 详情 → 收藏 → 我的收藏」，再完成「体验卡片 → 操作 → 保存并重开作品」，最后接入「我的」设置与非遗性格。阶段按交付和验收顺序排列，素材准备、界面开发和后端实现可以并行。

| 阶段 | 实现内容 | A、B、C 的任务 | 验收条件 |
| --- | --- | --- | --- |
| 0. 共用开发基线 | 确认团队使用的 `main` 提交、统一接口文档和本地启动方式。 | A 记录公共导航和主题入口。B 与 C 确认搜索、详情与收藏所需数据。三人都从同一个提交开功能分支。 | 三人能按 README 启动客户端与后端，用测试账号登录并打开现有图鉴详情。 |
| 1. 图鉴、搜索和收藏 | 先接关键词、分类和分页，再接详情收藏、取消收藏与「我的收藏」。用 3 条已审校的条目联调，并补齐这批详情的封面和来源。 | B 按契约开发搜索和收藏界面，用样例响应先跑通。C 实现图鉴筛选和收藏接口。A 可并行开发体验入口并确认从图鉴进入体验的导航方式。 | 搜索可结合分类，空结果有提示。收藏后重新登录仍可从「我的收藏」打开同一条目。取消后列表和详情一致，两个账号的收藏各自独立。 |

### 任务依赖和交接

- **搜索可以先独立验收。** 先确认 `GET /api/heritage` 的查询行为，再把收藏的列表、添加和取消一起交付。第一阶段以 3 条审校数据为联调基线。
- **体验入口先复用可操作的页面。** 将 360° 放在展馆，将自由临摹放在创作。关联体验需要可用入口和有效素材编号，临摹列表需要先实现本地草稿的保存与重开。账户皮影设计继续使用现有作品接口。
- **个人设置先于测评。** 页面美化与 AI 助手设置共用 `GET/PATCH /api/me/preferences`。题库、类型和计分规则确认后，再验收完整测评流程。
- **共享文件集中交接。** A 维护 `MainActivity`、导航、主题和 Manifest，B 在各功能文件实现页面，C 维护 `FeiyiApi`、`Repository` 和接口契约。涉及共享 `FeiyiViewModel` 的改动由 A 汇总接入，数据接口由 C 核对。每个功能 PR 由接手人按验收步骤复现。
- **待确认的范围单独排期。** 当前首轮按登录后进入主界面验收。访客模式、注销、找回密码、第三方登录、AI 对话和媒体社交增强待确认范围后再排入。

前后端联调及字段约定见[统一接口文档](接口文档.md)。
