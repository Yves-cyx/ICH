# 三人分工与修改边界

版本：2026-11-19 调整版。

## 主责

| 角色 | 人员 | 主责 | 主目录 |
| --- | --- | --- | --- |
| A | 陈翊轩 / Yves-cyx | 整体框架、整体 UI、导航、独立登录页 UI、戏台、集成 | MainActivity、ui、navigation、feature/experience、feature/login、feature/stage |
| B | 王浩铭 | 画布、建模与 360° 展示；其余原 A/B 功能：图鉴/百科、详情、搜索、“我的”、收藏和作品列表、设置 | feature/drawing、feature/viewer、feature/catalog、feature/profile、data/works |
| C | 季院升 | 后端、Android 网络接入、登录状态、收藏数据、共享模型；职责不变 | server、data/remote、data/auth、data/model、data/catalog |

“整体 UI”由 A 统一设计规范、公共组件和基础页面布局。B 在这些规范上实现自己模块的页面与功能，不另建主题、导航或网络层。
每个人负责自己代码的编译、异常状态和演示。A 负责最终集成，不代替 B/C 完成模块内部逻辑。
内容工作由 B 汇总 50 条清单，三人分批采集并交叉审校，A 审核视觉呈现。

## 先框架，再交接

1. A 先完成 T09：三入口、独立登录页、各功能占位页、可往返的导航、公共样式。
2. 框架阶段，A 可以创建 B 模块的基础布局；B 同时准备素材和业务逻辑，避免同时修改这些布局。
3. 框架 PR 合并后，A 在 PR 中列明页面文件、入口方法、参数和负责人；B 接手自己模块的文件。
4. C 可同步做接口/后端，不必等 UI 完成；接口先与 A/B 对齐。
5. 后续 A 修改 B 页面样式时，先在 Issue/PR 协调文件，避免同改。

## 跨模块交接

| 功能 | A 交付 | B 交付 | C 交付 |
| --- | --- | --- | --- |
| 登录 | 独立页面、表单、加载/错误 UI、登录后返回原入口 | “我的”读取会话并提供登录/退出入口 | 注册/登录/退出、会话状态与错误 |
| 图鉴/百科 | 基础布局、视觉规范与公共导航 | 列表、详情、搜索、分类、界面数据绑定 | 图鉴数据、Repository 与网络实现 |
| 收藏 | 公共样式与导航约定 | 收藏按钮/列表、状态呈现 | 收藏查询/增删与登录限制 |
| 本地作品 | 公共入口和样式 | 列表、读写、删除、打开、缩略图与格式 | — |
| 建模与 360° | 页面框架与视觉规范 | 模型制作、预渲染素材、序列查看器与交互 | 如需要则提供素材地址 |
| 戏台 | 完整功能、影人部件/关节规格与交互 | 按约定协助素材制作 | — |
| 画布 | 页面框架与视觉规范 | 完整功能、草稿与图片导出 | — |
| 设置 | 样式规范 | 设置页面与本地选项保存 | 账号相关操作 |

登录页不重复保存 Token：A 调用 C 的 AuthRepository，B 的“我的”读取同一份会话状态。
戏台由 A 独立实现；画布由 B 独立实现，基础画笔/舞台交互不互相等待。
建模沿用首版预渲染序列方案，暂不新增实时 3D 引擎范围。

## 共同文件

- A 维护 MainActivity、导航、主题、公共资源及 Manifest；B/C 提交接入需求，由 A 统一注册/调整。
- C 维护 contracts/api.md 与共享数据模型；变更前确认 A/B 调用处的影响。
- B 维护 contracts/works.md；作品页统一调用 data/works，不另写保存格式。
- Gradle / 依赖版本修改在 PR 标出，由 A 集成；三人不同时升级依赖。
- 资源按模块加前缀；共享组件由 A 放入 ui 或公共资源。
- GitHub 任务负责人文字已经落实到人；B/C 的 GitHub 用户名待补充，暂不创建虚假的 assignee 或 CODEOWNERS。

## 工作量安排

B 的模块较多，按“图鉴最小流程 → 画布 → 360° → 我的收尾”逐项推进。不要同时启动全部模块。A 框架交付后转入戏台开发；C 按“图鉴接口 → 登录 → 收藏”推进。
