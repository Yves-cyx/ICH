# 三人分工与修改边界

## 主责

| 角色 | 人员 | 主责 | 主目录 |
| --- | --- | --- | --- |
| A | 陈翊轩 / Yves-cyx（暂定） | UI、导航、图鉴、详情、搜索、360°、“我的”页面、集成 | feature/catalog、feature/viewer、feature/profile、feature/experience、ui |
| B | 待认领 | 戏台、画布、作品可编辑数据、本地保存和图片导出 | feature/stage、feature/drawing、data/works |
| C | 待认领 | 后端、Android 网络接入、登录状态、收藏数据、共享模型 | server、data/remote、data/auth、data/model、data/catalog |

A 是集成人，不代表必须替其他成员完成接入。每个人负责自己的代码编译、异常状态和演示。
内容工作：A 维护 50 条清单与呈现规范；三人各分一批采集、交叉审校。B 提供皮影/临摹体验素材规格，A 提供环视序列规格。

## 共同文件

- A 维护 MainActivity、导航、主题、公共资源命名及 manifest；B 提出页面注册需求并在同一 PR 接入。
- C 维护 contracts/api.md 与共享数据模型；修改前让消费该接口的人确认。
- B 维护 contracts/works.md；A 使用约定读取作品，不能另写一套保存格式。
- Gradle / 依赖版本 / Manifest 改动在 PR 标出，由 A 合并。禁止三人同时独立升级依赖。
- 不跨目录顺手重构。确需改其他人文件时，在任务中写明文件与目的。

## 首次认领

在 docs/首批任务.md 或对应 Issue 记录真实负责人。两位同学的 GitHub 用户名补齐后再添加 reviewer / CODEOWNERS；本仓库暂不配置虚假的账号归属。
